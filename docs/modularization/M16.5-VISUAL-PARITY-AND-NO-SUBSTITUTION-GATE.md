# M16.5 Visual Parity and No-Substitution Gate

## Binding decision

The jointly reviewed M16.5 demo is the binding interface specification for the
productive Luvia product. The implementation is allowed to arrive in measured
slices, but the completed product is not allowed to be an interpretation,
approximation or stylistic echo of that demo. It must preserve the accepted
composition, information architecture, visual language, responsive behavior and
motion grammar while replacing fixtures with real owner-contract data and actions.

`config/luvia-m16.5-visual-parity-contract.json` is the machine-readable release
contract. Its key-file hashes pin the accepted local reference state from
2026-08-25. The public M16.5 preview remains a convenient review surface; the
recorded hashes, not a mutable URL, identify the accepted reference inputs.

## What the current local candidate means

The M16.5H candidate replaces the productive outer Signed-in shell. It is an
intermediate adoption state, not the final redesign. Existing inner Plan, Places,
Booking, Journey, Trip, Memories, Profile and overlay compositions remain visible
until their respective adoption slices replace them. Their presence may not be
reported as complete visual parity.

Each surface is complete only when all of the following are true:

1. the accepted reference composition is present;
2. the feature uses its real public owner contracts and actions;
3. the active Trip accent is projected consistently;
4. desktop and mobile layouts preserve the same product idea;
5. motion, shared-element continuity and reduced-motion behavior are measured;
6. loading, empty, error, offline, permission and consent states are designed;
7. keyboard, focus, semantics, contrast and safe areas pass;
8. the complete surface receives joint visual acceptance.

## No-substitution rule

A redesigned header around a legacy screen does not pass. A recolored legacy tile
wall does not pass. Feature removal does not pass. Desktop-only completion does not
pass. Demo fixtures may never become Domain Truth. Real runtime constraints may
change content, safe-area geometry and state presentation, but may not silently
replace the accepted design concept.

## Release lock

Integration may carry immutable review candidates. Main and Production remain
locked while any mandatory parity-matrix row is pending. Unlock requires complete
desktop and mobile evidence, full regression, exact Runtime provenance and explicit
joint acceptance. Until then, every candidate is labelled as an intermediate M16.5
adoption build.

No database migration, RPC, RLS, bucket, Edge Function, secret, manual Cloudflare
setting or Production mutation belongs to this documentation and guardrail slice.
