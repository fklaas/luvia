# M16.5 Complete Visual Product Redesign — Entry Baseline

Date: 2026-08-24

Status: READ-ONLY BASELINE / DESIGN NOT FROZEN

Runtime observed: Production App/Core `13.82.48 / 4.82.48`

## Binding scope

M16.5 is the start of Luvia's complete visual, graphical and interactional
redesign. It is not a sample-screen reskin and not displaced by Admin, Social
or Git stream work.

The current visual language is replaced. The proven Domain contracts, state
machines, data, commands, confirmations, receipts, recovery and accessibility
semantics remain inputs to the new design.

## Exhaustive inventory gate

No Design Freeze is valid until the inventory covers:

- every active, hidden and deep-linked screen;
- every top-level and secondary navigation destination;
- loading, skeleton, empty, success, warning, error, offline, stale, denied,
  confirmation, pending, partial failure, unknown outcome, recovery and receipt
  state;
- dialogs, sheets, overlays, popovers, menus, toasts, tooltips and keyboard/
  safe-area behavior;
- cards, boxes, containers, lists, tables, forms, filters, maps, galleries,
  media, search and AI Rich Results;
- Hover, Press, Focus, Drag, Scroll, selection, transition, entrance/exit,
  loading and feedback motion;
- desktop, tablet, mobile Web and the planned SwiftUI/Compose adaptations;
- every relevant tracked CSS, HTML, SVG/image/font, Experience/UI/Design file,
  DOM-rendering JavaScript module, inline style/template and active runtime
  asset.

`scripts/m16.5-visual-surface-inventory.cjs` produces the repeatable file and
asset manifest. A fresh manifest and zero unreviewed candidate files are later
Design-Freeze gates.

The corrected Social/20-stream candidate manifest covers 2,744 tracked files,
classifies 650 visual candidates, resolves 261 active entry references and
leaves zero active entry references unclassified.

## Measured source debt

Read-only repository measurement at the M16 marker found:

- 58 tracked CSS files;
- 837,078 canonical LF CSS bytes;
- 6,157 physical CSS lines including final-line accounting;
- 3,219 `!important` occurrences;
- 2,845 literal hex-colour occurrences using the deterministic manifest regex;
- 226 `z-index` declaration occurrences;
- 35 reduced-motion query occurrences;
- 36 `:focus-visible` selector occurrences.

These figures are inventory, not a deletion target by themselves. Legacy or
duplicated visual code is removed only after reachability, replacement and
rollback are proven.

The first shell measurement reported 839,180 bytes, 6,100 lines, 3,178 colour
matches and 182 z-index lines because it used `rg` line-oriented counting over
the working tree. An initial manifest draft then reported 843,165 raw
Working-Copy bytes and failed correctly after Integration checked out the same
Git blobs with CRLF. The checked-in manifest is the canonical repeatable
baseline: it normalizes text to LF, counts declaration occurrences and records
a SHA-256 for every candidate while leaving binary assets byte-exact. All three
observations are retained rather than silently rewritten as identical.

## Live surface observations

The authenticated Production sample showed:

- Today with active Trip identity, large destination hero, Trip attention,
  Journey Day Graph, Luvia Intelligence card and collaboration presence;
- five-item bottom navigation: Today, Plan, Trip, Memories and More;
- global Luvia conversation trigger and invite/profile actions;
- Control Center as a Consumer-owned travel/attention projection;
- Profile and Security shell with trip, profile, preferences, dashboard,
  settings, security, export and logout entry points;
- no global Admin role/grant/policy/approval/break-glass/audit surface.

The current Control Center is not the Admin Experience. M16.5 designs an
independent administrative composition backed later by Admin contracts.

## Current visual diagnosis — not a style decision

The sample confirms the user's diagnosis: repeated pale pink gradients, large
white cards, mixed emoji/icon language, inconsistent density, weak hierarchy
between product and system information, limited spatial variety and little
coherent motion make the product simultaneously playful and static. This is a
baseline problem statement, not permission to silently choose a replacement
style.

## Complete redesign systems

M16.5 must define:

1. Corporate Design: brand idea, logo rules, typography, colour, imagery,
   iconography, illustration, maps, data visualization, voice and sound/haptic
   direction.
2. Active-Trip accent semantics: contrast-safe roles for primary action,
   selection, highlights, chosen headings, outlines, focus, gradients and
   motion with colour-blind fallbacks.
3. Layout system: grids, spacing, type scales, density modes, responsive
   breakpoints, safe areas, split views, lists, editorial and map compositions.
4. Component system: buttons, inputs, selectors, cards, containers, tables,
   navigation, search, chat, Rich Results, calendars, maps, media and admin
   controls.
5. State system: the complete state matrix above, never only the happy path.
6. Motion system: spatial model, durations, easing, choreography,
   microinteractions, feedback, reduced motion, power/battery and performance
   budgets.
7. Platform adaptations: Web, SwiftUI and Compose share semantics while using
   native navigation, sheets, controls and haptics.
8. Accessibility: keyboard, focus, touch targets, contrast, text scaling,
   screen readers, motion sensitivity, localization and cognitive clarity.

## Administrative Experience requirements

The Admin surface joins the same Corporate Design while remaining a serious,
high-density operational tool. Required designed surfaces and states include:

- overview/security posture;
- user and service-principal directory;
- roles, capabilities, scopes and effective-access explanation;
- permission matrix and before/after policy diff;
- grant/revoke/delegation with expiry;
- approvals inbox and four-eyes flow;
- audit explorer and correlation trail;
- incident, session revocation and break-glass console;
- denied, step-up required, awaiting approval, stale policy, unknown outcome,
  partial failure, recovered and receipted states.

Admin UI must never imply that a visible control grants permission. Disabled,
hidden and denied states are presentation; server policy is authoritative.

## Social Travel Intelligence Experience requirements

Social joins the same Corporate Design as contextual utility across the
product, not as an endless feed or a generic attached tab. M16.5 designs:

- Travel Twin evidence, uncertainty and privacy controls;
- Social Compass explanations in Places, Journey and Luvia AI;
- Fork my Trip source, adaptation, confirmation and provenance;
- Echo arrival, source-memory, defer, expiry and consent states;
- Experience Drop creation, audience, moderation and relevant-time delivery;
- verified versus community evidence semantics;
- circles, connection, block, report, audience and reuse consent;
- Social Booking inspiration and owner-handoff receipts;
- all empty, loading, stale, denied, blocked, revoked, expired, moderated,
  offline, unknown-outcome and recovery states.

These surfaces inherit active-Trip accents, accessibility, motion and native
adaptation semantics. Their design does not grant Social permission to copy
foreign Domain Truth.

## Joint design sequence

1. Generate and review the complete visual file/asset manifest.
2. Enumerate every route, module, overlay and state from runtime and source.
3. Benchmark relevant travel products plus motion references; do not copy.
4. Produce two to three genuinely different Creative Territories.
5. Review territories with the user and select one direction or an explicit
   hybrid.
6. Build Corporate Design and design tokens.
7. Prototype priority flows end-to-end: Today, Plan/Places, Journey, Booking,
   Memories, Profile, Luvia AI, Social Travel Intelligence and Admin.
8. Expand to all screens and complete state matrix.
9. Validate Web/mobile/native adaptations, accessibility, motion and
   performance.
10. Obtain explicit user Design Freeze.

M17 starts broad implementation only after step 10. Until then, no commentary,
mockup or isolated screen is represented as the approved final design.
