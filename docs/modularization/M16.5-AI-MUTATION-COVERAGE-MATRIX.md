# M16.5 AI Mutation Coverage Matrix

Status: Step 15 public counterexamples recorded; S16.01–S16.06, S16.08 and S16.09–S16.12 are implemented locally with contract/eval coverage. S16.07 remains explicitly reserved. This ledger describes executable coverage, not product intent. A row is not `PUBLIC-E2E-PASS` unless a human-visible Integration run has exercised it through the real control path.

## Invariants

- OpenAI may understand, split, order and explain a request. It never becomes the owner of Trip, Places, Booking, Journey, Memory, Media, Identity, GPS or Collaboration truth.
- `READ/R0` may run automatically through a public owner read. Every state-changing action starts with a visible preview or an owner-owned draft surface.
- `EXPLICIT` means that natural-language text alone is never confirmation. Execution requires a separate user gesture, the public owner command, an Owner Receipt and the registered Recovery policy.
- `USER_GESTURE` opens an owner surface or draft. It is not permission for the external or durable mutation that may follow inside that owner flow.
- A missing provider, owner adapter, required input, verified capability or current source blocks the affected action. The chat must show recovery or refinement and must not invent evidence.
- Main, Production, DB/RLS, Secrets and Edge Functions are outside this Integration tranche.
