## Invariants

- OpenAI may understand, split, order and explain a request. It never becomes the owner of Trip, Places, Booking, Journey, Memory, Media, Identity, GPS or Collaboration truth.
- **Human ↔ AI action parity has no product exception.** Every operation exposed to an authenticated user must have an equivalent chat intent and must call the same public owner command with the same permission boundary. If the user can perform an operation but the chat cannot, the affected product surface is `PARTIAL` and the release gate remains open.
- Human ↔ AI parity includes reads, navigation, drafts, creates, updates, links, moves, cancellations, deletions, exports, sharing, consent, group decisions and every future public action. The AI receives no shadow write path and no authority beyond the acting user.
- Adding a public UI command without adding its AI route, deterministic input contract, confirmation policy, receipt, recovery/undo policy, eval and visible Step-17 evidence is a parity regression.
- `READ/R0` may run automatically through a public owner read. Every state-changing action starts with a visible preview or an owner-owned draft surface.
- `EXPLICIT` means that natural-language text alone is never confirmation. Execution requires a separate user gesture, the public owner command, an Owner Receipt and the registered Recovery policy.
- `USER_GESTURE` opens an owner surface or draft. It is not permission for the external or durable mutation that may follow inside that owner flow.
- A missing provider, owner adapter, required input, verified capability or current source blocks the affected action. The chat must show recovery or refinement and must not invent evidence.
- Main, Production and secret creation remain outside this Integration tranche. The user separately authorized the additive Hotel provider schema/RLS and Integration Edge gateway; those changes remain deny-default and create no connected-provider claim without separately supplied credentials and provider approval.
