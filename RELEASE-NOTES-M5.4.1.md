## Architecture change

M5.4.1 removes active private TripStore consumption from `intelligence/destination-service.js` and routes that consumer through the public Trip Contract.

The Trip-owned boundary now exposes `applyResolvedDestination(tripId, destination)`. The command reads the canonical owned Trip, derives the updated destination projection and performs one canonical local TripStore upsert. It deliberately does not use `TripExperience.update` and does not add the existing `luvia_save_trip_profile` cloud-write path.

The migration preserves the Destination Registry, Legacy compatibility mirror and Trip Context refresh behavior required by the current Web runtime.
